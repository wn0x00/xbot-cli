# 临时测试变更与恢复

仅用于获准的复现或维护测试。只读任务、明确禁止修改的任务不改参数或源码。临时变更用于建立测试条件，不属于正式修复或交付。

先查现场 schema，优先使用实际支持的运行输入，不能传值才在任务范围内临时调整参数/测试辅助。不猜 flow run 支持某个传参 flag。读取实际入口及调用链，核对 test() 固定值、提前退出、浏览器/页面来源，确保本次值确实进入原业务函数。

## 建立和留存

按 [变更备份](application-git-backup.md) 记录对象身份、原文/原值、方向/类型、插入位置、所有权及恢复方法。写后回读源码、参数和接线；“参数已写”不证明调用消费了参数。正式默认值与临时测试值分开记录。

允许临时辅助的任务，可改既有 test()/test_*，缺失时临时创建并接入原业务调用；普通应用也适用，但不注册为公开指令、不保留为正式入口。复现原问题时不修改原业务函数，不另写一套实现代替被测逻辑。只读或明确禁止辅助修改时停止这条路径，继续可做的分析。

普通应用正式交付仍由正常主流程运行，保留原工程结构；仅为复现的函数、接线、临时默认值结束后移除/恢复。原有测试函数保留完整原文，新函数记录修改前不存在的证据。

## 测试条件

优先原入口/调用链重建前置；允许的 CLI 观察或辅助动作单独记录，不能当作 Flow 完整复现。已有登录态可以核验后使用，不清会话、不关闭他人窗口。路径/测试数据可以按代表性映射，但缺陷相关的格式、空值、编码及业务约束要保留，见 [环境映射](environment-and-paths.md)。

临时依赖只在获准应用 venv 处理；不要为准备条件自动升级系统、换账号、转移登录态或执行未授权业务动作。每次执行按用户预算和重复安全判断；超时先查原运行，不重新启动。

## 恢复

1. 等原运行到可安全恢复的终态；未知时报告占用/残留，不热改。
2. 用原通道恢复原值/原文，删除本次新增函数及接线；仅撤临时差异，保留正式补丁及其他人的修改。
3. 回读参数、源码、调用关系与相关静态结果。依赖/文件/浏览器资源仅按本次所有权及授权清理，故障证据和未知业务对象保留。
4. 回读一致才写 restored；失败/未确认记录 failed/unknown、具体残留及下一步。不把未验证写成已恢复。

报告可简记：对象、原状态→临时值、用途、实际消费证据、恢复状态及残留。无临时改动无需编造恢复步骤。
