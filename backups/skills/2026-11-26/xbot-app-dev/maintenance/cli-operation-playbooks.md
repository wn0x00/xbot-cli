# 常用维护操作方案

每个命令先查现场 help/schema，输出/上下文语义统一见 [CLI 契约](../references/cli-contract.md)。以下是路径选择，不是另一份参数手册。

- **已知资产 ID**：检查当前占用 → 按 ID 读取/正常打开 → 回读身份、流程和参数。需要只读时可用查看模式；需要保存再用编辑模式。不强制关闭已有草稿。
- **CodeFlow 修改**：读取当前源码及 In/Out → 受影响原文备份 → 精确 edit → 回读 → check → 获准的运行及业务验收。写入后诊断失败先读实际阶段，不整批重做。
- **VisualFlow 修改**：读取真实块及 form → 最小 edit/fill → 只处理 fill_errors 指定的失败块 → 回读和验收。不猜分组参数或块字段。
- **运行超时**：保留原 run_id/task_id → 只查询原运行与业务回执 → 终态后再决定；不跨 task/flow/oapi 重启。
- **网页定位**：查前置和真实对象 → 用途单元素/集合分类 → 独立身份基线 → 候选/拒绝路径验证 → 最小接入。当前零匹配不是原用途证据。
- **Windows 动作无效**：核对目标子控件 ref、实时 bounds、实际 execution 方法/点位与界面效果。默认 physical，invoke 备选；先补快照及对账，不能自动再点。
- **临时复现**：普通应用及指令集均按 [临时变更](temporary-values.md) 留存/恢复；普通应用正式交付不保留新增测试入口，指令集测试辅助不公开。
- **元数据变更**：只在对应指令集任务进入 [专用流程](../../xbot-development-standards/references/metadata-delivery.md)，不让普通修复执行全套注册维护。
- **保存/同步/发布**：分别确认实际任务范围和证据，见 [恢复](../references/recovery.md)。没有“只关闭、不上传”的 sync 语义。
