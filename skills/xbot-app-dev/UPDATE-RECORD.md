# v9 到 v10 更新记录

版本：**v10**。更新日期：2026-10-22。

v10 在网页探索、CodeFlow/VisualFlow 开发与验收基础上，新增算法生成 XPath、定位修复辅助、用途分析、相似元素组验证和 Python Windows 单控件修复模块。

## 2026-10-30 CLI 0.9.1 补充

Skill 版本仍为 v10。浏览器契约补充 Web 操作附带影刀 Python、`web xpath <ref...>` 至多 5 组备选/相似元素规则、iframe Selector 分层、open shadow 待影刀验证与 closed shadow 拒绝生成。CLI 契约同步说明安装目录自动发现和具体路径诊断。本次随 CLI 0.9.1 更新，不把候选生成或离线测试写成影刀运行通过。

## 升级基础

v9 提供从真实 DOM 获取和验证 XPath 的工作规范，未配套算法生成器和可执行修复脚本。v10 新增 ROBULA+ 与加权生成器，以及相应分析、提议和复核链路。

网页探索、CodeFlow/VisualFlow 开发、命名规范、静态检查、实际运行和业务验收继续支持。有效新旧定位兼容、同节点去重、歧义停止、最小修改和结果未知先核对等原则继续沿用，并补充执行检查。

Skill 从 v9 的 14 个文件扩展到 38 个文件，包含 Web/Windows 模块、12 个脚本及分析/修复模板，按任务加载所需资源。

## Web 新增能力如何工作

### 1. 算法生成 XPath

```text
当前完整快照 ref
 -> aria-ref 解析真实节点句柄
 -> 确认所在文档、iframe 和 open ShadowRoot
 -> ROBULA+ 与加权算法分别生成候选
 -> 在真实上下文逐段查询
 -> 必须唯一命中同一个实际节点
 -> 输出主候选、备选、算法错误和上下文证据
```

ref 不是 XPath 编码，不能仅根据 `e12` 等编号反算路径。AI 确认业务对象，算法描述当前节点；生成后的身份回查负责防止路径指向另一个对象。

加权算法优先考虑业务/测试属性、稳定 ID、名称和区域关系，并过滤部分动态 ID、样式类与会话 URL。它支持属性两两组合、五层祖先锚点、特殊字符和节点类型处理、生成预算及标记为结构型的回退路径，并输出成本与采用原因。ROBULA+ 提供另一套独立候选，两者分别记录结果、预算和失败原因。

### 2. 旧 XPath 找不到时修复

先排除登录失效、未加载、错误页面、权限和通道故障；再读取可信的原目标身份，确认当前唯一候选，最后生成新路径。ROBULA+ 本身不恢复业务意图，也不会监控页面并自动修好流程。

`capture/diagnose/propose/revalidate` 是 Skill helper 的入口，不是新增的 `xbot-cli repair` 命令。它们只读观察和输出提议，不改流程、不点击、不保存影刀元素库。Agent 需要另行完成隔离测试、最小写入、回读和业务验收。

当前单元素参考适配器要求 `data-contract-v1` 页面身份字段。真实网站需映射其可靠业务身份；只有失效 XPath、没有历史身份时停止自动采用，不能用当前候选反造基线。

### 3. 相似元素组和父子依赖

AI 根据原流程反推“取一项还是遍历一组、每项读什么、怎样筛选、后续会发生什么”。当前匹配数为零不能判断原用途。集合查询后按业务键选择一项，仍属于集合修复。

集合解析器逐项检查业务键、字段和独立清单；父定位变化时同时检查 `./` 子查询。不同区域都满足合同、漏成员、重复键、子字段多匹配或动作对象不明时停止。旧新版本命中同一真实实例才去重，不按文本相同合并。

这些是有明确合同的普通 DOM 参考能力。尚无通用重复祖先自动发现、任意网站集合规则生成或完整跨函数数据流分析；集合也不能直接交给原单元素 ROBULA+ 修复器。

### 4. iframe 和 Shadow DOM

iframe 用路径数组，open ShadowRoot 用段内 `/xbotShadowRoot`。这是影刀 Selector 协议，不能拼成普通 XPath 交给任意 XPath API。

已验证部分单元素组合及工程 Selector 执行；closed ShadowRoot、ShadowRoot 内 iframe、未适配的 frame transform/zoom，以及复杂上下文集合修复仍有限制。生成成功与操作成功分别验收；XPath 生成不会自动创建影刀元素库资产。

## Windows 新增能力如何工作

当前优先路线是 **Python + uiautomation**，无需影刀元素库或 Agent 逐次回传快照。编码版执行 Python helper，可视化通过 `process.run` 调用同一个编码版。实际业务目标是微信等程序，按原流程确认目标窗口。

```text
原错误和失败调用
 -> 确认业务程序窗口与单控件用途
 -> 查询所有旧新定位，检查完整原身份
 -> 全部零匹配时寻找唯一可信候选
 -> 在新资产副本追加定位，保留旧资产和旧变体
 -> 隔离测试、动作前复核、动作后验收或对账
```

当前严格核对可执行文件路径、窗口类、系统标题、控件属性和有序必要祖先；不靠模糊名称、坐标或最高相似分强改。身份变化、候选歧义、树观察不完整、集合用途和环境异常均停止。

微信发送适配增加群聊核对、同名结果消歧、搜索层检查、本地操作台账和只读对账。存在 `Invoke` 接口不等于消息发出；发出动作后的观察失败属于结果未知，不进入另一轮定位修复和重发。

`xbot-cli win32 snapshot` 是本地构建的实验性只读 UIA 能力；Skill 内也有 Python 快照脚本。Windows-MCP、Umbriel 仍仅调研。旧 `sky.window2` helper 留作独立历史通道，资产不能与 UIA 混用。

## 能力边界与待优化点

- **身份仍是前提。** 观察字段一致、路径唯一，也可能对应不同后台对象；同内容替换与业务绑定变化仍有误识别风险。
- **AI 分析并非全自动可靠。** AST 目前保守支持直接 XPath API 和简单常量；动态封装、跨函数/子流程和 VisualFlow 用途自动交接仍有缺口。
- **集合完整性需要独立数据。** 尚无通用分页/虚拟列表遍历协议，复杂上下文集合和 Windows 集合未完成。
- **Windows 验证范围有限。** 目前本机单个微信客户端、单控件修复；跨电脑、实际改版、多语言、自绘控件和远程环境未验证。
- **观察与动作之间存在变化窗口。** 复核不是事务；Python UIA 的预算不能强行中断卡住的 COM/provider 调用。
- **依赖需单独准备。** ROBULA+ 源码未打包，需提供固定修订并校验哈希；Node 须支持 `stripTypeScriptTypes`。Windows Python 需安装 `uiautomation==2.0.29`。具体要求见模块引用。
- **不是常驻自愈服务。** Agent 仍负责根因分析、模块选择、补充合同、编排测试和修改流程；没有任意报错后无人值守续跑的承诺。

后续优先补可靠业务身份与对象绑定、多电脑/真实改版回归、同内容替换检测和动作对账；再完善 Windows 集合、iframe/Shadow 集合、跨流程分析及独立 worker 超时。
