# 验证与交付

按修改范围选择必要检查，不为一次小修要求所有平台回归。新变更、失败或具体疑点才扩测；已有必要检查通过后继续交付。

## 验证证据

1. 回读目标身份、源码/块、参数及接线，确认实际写入范围；保留精确 diff。
2. 静态检查发现的问题与运行结果分别记录；flow check 不运行业务。
3. 获准时按真实入口运行并检查输出、业务对象及关键后置条件。指令集辅助复用原实现，普通应用通过主流程核验；临时复现辅助不替代整体业务证据。
4. 按风险验证受影响正常路径、失败/超时/部分完成、定位歧义或旧调用兼容。不可取得的环境/旧页面标为未验证。
5. 动作已可能生效后只查结果，不为验证再做一次。独立业务回执比工具返回更强；客户端消息可见也不证明服务端送达。

确定性静态缺陷可在修复授权内改并针对性验证，但保留“原故障未动态复现”的范围说明。有效测试未复现且无充分缺陷依据时不猜补丁；还没到失败路径则是条件阻塞。

## 失败与恢复

写入失败先查 applied/partial 及现状。恢复源见 [备份](application-git-backup.md)，仅恢复本任务差异；运行中/结果未知不自动回滚。恢复状态区分 not_needed、patch_reverted、patch_residual、revert_failed、unknown。

无论测试结果如何，都按 [临时恢复](temporary-values.md) 处理测试参数、辅助函数和接线，回读一致才确认恢复。清理只限本任务资源，不能顺手删用户窗口或未知结果业务对象。

交付报告区分已写入、静态通过、运行通过、本机业务通过、已同步、已发布和用户端恢复。未获授权不发布/同步/推送。只有指令元数据变更才核对真实保存与完整关闭重开，脚本标签、相同 hash 或 reload 回执不能单独替代该证据。

用户明确要求独立验收时才提交候选给指定验证者，不因没有第二个 Agent 阻塞普通验证；不自行发消息或配置协作。报告按 [结果模板](report-contract.md) 选择必要字段。
