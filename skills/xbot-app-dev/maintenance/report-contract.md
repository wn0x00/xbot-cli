# 结果报告

普通任务用简洁中文说明结果、修改、验证和限制。复杂故障/多人交接再填下表，不要求每次把空字段全部输出。

| 字段 | 必要事实 |
| --- | --- |
| 目标与范围 | 用户授权、资产/流程 ID、故障版和编辑基线、执行端 |
| 问题与根因 | 失败行/块、预期/实际、前置、直接证据/推断/未知 |
| 实际尝试 | 输入摘要、真实入口、run_id/task_id、到达路径、结果 |
| 变更 | 受影响调用点、契约兼容、原文备份/差异、候选 |
| 验证 | 写入、静态、运行、业务分别给实际结果与证据 |
| 恢复 | 临时参数/函数/接线恢复回读，补丁恢复状态与残留 |
| 交付状态 | 本地保存/同步/发布/用户端验证分别列事实 |
| 后续 | 具体缺口、影响、可执行的下一步 |

状态可用：not_run、blocked、not_reproduced_under_tested_conditions、outcome_unknown、fix_candidate、runtime_verified、business_verified、published、user_recovered。它们可并列描述不同阶段，不是必须走完的发布链路。

独立 Windows 任务记录 snapshot_id、backend、HWND/PID/进程实例；网页任务记录浏览器/页面上下文及快照。已有任务 ID 必须使用真实返回值，不编造截图、文件或链接。日志/输入仅保留必要脱敏摘要。

“写入成功”不能写成“业务通过”，“本机通过”不能写成“用户已恢复”。没有真实运行就明确未验证；没有发布回执就交付候选，不默认为已经上线。请求只读分析时，静态证据本身可以完成任务，无需运行或修改凑结果。
