# 网页自动化维护与恢复

当网页流程失败、页面改版、元素失效、登录过期、运行超时或用户要求维护已有自动化时读取本文。

## 固定维护顺序

```text
读取 error/data
  -> 判断动作是否可能已经生效
  -> 查询当前浏览器或 Studio 状态
  -> 获取最新 snapshot
  -> 区分页面变化、选择器失效、会话失效、权限问题和业务失败
  -> 只修改受影响步骤
  -> dry-run
  -> flow check
  -> 回归受影响用例
```

维护 Studio 应用时：

```powershell
xbot-cli status --json
xbot-cli app open <app-id> --json
xbot-cli flow list --expect-app <app-id> --json
xbot-cli flow get <flow-id> --expect-app <app-id> --json
```

CodeFlow 优先 `flow code edit` 做精确替换；VisualFlow 只编辑目标块，`fill_errors` 出现时只修复失败的 block_id。不要因为一个元素失效而整份重写应用。

## 错误处理

| 错误或症状 | 处理 |
|---|---|
| `MCP_OFFLINE`、`SHELL_CLI_MISSING` | 停止后端操作，检查客户端、登录态、安装路径和 MCP 端口 |
| `MCP_TOOL_FAILED` | 读取真正的 `error` 和 `data`，不要被 selector 暂存提示覆盖 |
| `WEB_SNAPSHOT_FAILED` | 保留原动作成功证据，只补 `web snapshot` |
| `MCP_BAD_RESPONSE` 或连接中断 | 先读取当前页面状态；动作可能已执行，不直接重放 |
| ref 找不到或元素类型变化 | 获取新快照，重新选择语义匹配元素；填写只能针对可编辑元素 |
| `FLOW_STATIC_ERRORS` | 先修 `data.static_errors`，此时流程尚未运行 |
| `FLOW_FILL_FAILED` | 只修 `fill_errors` 中的 block_id，其他已应用修改不要整批重试 |
| `FLOW_RUN_TIMEOUT` | 保留原 `run_id`，使用 `flow wait`，不要启动第二份 |
| `FLOW_RUN_PAUSED`、`FLOW_RUN_STOPPED` | 停止自动操作，等待用户决定 |
| `VIEW_MODE_READONLY` | 关闭只读 View，用 `app open` 重新进入编辑模式 |
| `studio_already_open` | 先读取当前应用并保存已有工作，不直接使用 force 切换 |

## 重试策略

只有确认前一次动作没有发生，并且动作具备幂等性时才重试。以下情况默认禁止自动重放：

- 点击提交、删除、发送、支付、发布或修改账户设置
- 输入后触发搜索、保存或提交的按键
- 网络超时但响应可能已被后端接收
- 动作成功但后续快照失败
- 写入成功但诊断、回读或日志查询失败

对未知结果，先查询状态、页面、日志或任务标识。`retryable=true` 只表示错误可能恢复，不表示整个写入或动作可以安全重放。

## 页面改版修复

先用当前快照确认目标身份；快照不足时用只读 `web eval` 检查 DOM 和作用域。网页流程优先修复为已验证的 XPath：VisualFlow 用“获取元素对象（web）”的 XPath 模式，CodeFlow 用 XPath API。只有确需保留的元素库资产或不支持直接 XPath 的场景才使用命名 selector，命名遵循 [项目规范](project-conventions.md)。

不要用新定位直接覆盖仍有业务场景使用的旧定位。先确认旧版、新版及共存场景；只有已经验证有效的旧定位才能保留为候选，原先过宽、已错误匹配的定位不能原样加入回退。

### 新旧元素兼容与共存消歧

为同一业务目标维护旧版和新版候选及各自页面条件。先确认页面、frame、弹窗或记录行，再在该范围内分别统计候选，检查可见性、可操作状态和业务身份；同一 DOM 元素被两个 XPath 命中时按元素身份去重，不能仅按文字相同认作同一元素。用当前 SDK 支持的身份判断或实时 DOM 只读证据确认，不假定两个 Python 包装对象的 `is` 比较就能判断 DOM 身份；无法确认时保留歧义。

| 观测状态 | 处理 |
|---|---|
| 仅旧版有效且唯一 | 使用旧版，保留新版候选供适用页面使用 |
| 仅新版有效且唯一 | 使用新版，保留仍有适用场景的旧版候选 |
| 两个候选指向同一 DOM 元素 | 去重后确认身份，只操作一次 |
| 新旧元素共存，但只有一个处于当前有效区域且可见可操作 | 排除隐藏模板或非活动区域中的副本，选择当前有效目标 |
| 新旧元素均可见或某个候选仍匹配多个元素 | 用页面版本标志、所属行、弹窗、活动区域或业务键继续缩小范围；仍不唯一就停止并报告歧义 |
| 两者均无有效目标 | 在总等待预算内等待页面状态；到期明确失败，不点击相似元素 |

版本优先级只能在已证实的页面条件下使用，不能仅凭“新版优先”掩盖两个不同目标共存的情况。目标禁用或等待状态未满足时，按业务条件等待或失败，不跳到另一个副本绕过状态。

不要使用宽泛的 XPath `旧版 | 新版` 再取第一项，也不使用 `[1]`、列表首项或“捕获任意异常后重试另一元素”消除多匹配。查找和消歧在动作前完成，动作只发出一次；若动作结果未知，先查询页面/业务结果，不切换候选重放。

等待、候选检查和重新定位共用有界时间预算。记录选中版本、页面条件、各候选匹配数和最终目标身份；DOM 变化后重新定位，不能复用已经失效的元素对象。注册格式见 [定位记录模板](../templates/locator-registry.json)，它不是自动执行配置。

修复后至少回归：

- 正常路径
- 仅旧版、仅新版、新旧共存（同一元素、隐藏副本、不同可见目标）以及均无匹配；共存歧义未消除时动作次数应为 0，唯一目标确认后动作次数应为 1
- 空结果或无匹配路径
- 登录过期或权限不足路径
- 受影响的提交、下载或输出步骤

旧版页面等状态暂时不可用时标为未验证，记录缺口；不能据此声称已兼容。不要为构造测试在真实页面上注入旧控件或复制按钮。新增验证逻辑放到“测试”分组的对应 `测试_动作名` 流程，并复用“业务”分组中被测动作。

不要把完整页面、Cookie、Token、密码、验证码或无关日志写入维护报告。
