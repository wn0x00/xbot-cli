# 元素、代码命名与流程组织

创建或维护应用、流程或元素库时读取本文。这些是本工作区的项目规范；官方 Wiki 中“默认使用工程 selector”的建议不覆盖这里明确的 XPath 优先要求，实际 API 能力仍以当前 schema 和 SDK 为准。

## 元素库命名

需要使用影刀元素库时，新增元素或本次明确需要改名的元素按下列格式命名：

| 类型 | 格式 | 示例 |
|---|---|---|
| 点击操作目标 | `平台名_业务含义_按钮` | `TEMU_售罄看板_按钮` |
| 输入目标 | `平台名_业务含义_输入框` | `百度_搜索_输入框` |
| 等待、判断存在或页面就绪 | `平台名_业务含义_标志` | `TEMU_售罄看板加载完成_标志` |

- 平台名统一使用项目约定的名称；业务含义要能区分页面、区域和动作，不使用“按钮1”“临时元素”等名称。
- `_标志` 表示该元素用于等待或存在性判断，不将它当作点击按钮或输入框使用。
- 确需分别保存新旧版本时，将版本放在业务含义中，保留类型后缀，例如 `TEMU_售罄看板旧版_按钮`、`TEMU_售罄看板新版_按钮`。
- 改名前检查引用范围；保留无关的既有名称和已发布调用契约，不为套用规范批量改名。XPath 直接定位不要求额外创建元素库条目。

## 编码版变量命名

- 新增 Python 变量和函数参数默认使用英文 `snake_case`：小写英文单词之间用下划线连接，例如 `search_keyword`、`target_element`、`retry_count`、`is_page_ready`。尽量避免中文变量名，不混用驼峰命名。
- 新建 CodeFlow 的 In/Out 参数也优先采用英文 `snake_case`。维护已有流程时保留已声明的参数名、外部字段和 SDK 接口；既有中文键名在输入输出边界映射为英文内部变量，不擅自改变对外契约。
- 中文页面文本、XPath 中的中文内容、日志文案、流程显示名称和元素库名称属于业务文本，继续遵循各自规范，不因代码变量命名规则机械替换。
- 需要重命名已有内部变量时，同步检查定义、引用和作用域；一次局部修复不顺带批量重命名无关代码。

## 流程分组

新建应用或明确要求整理流程时，采用以下层级：

```text
配置
  对话框配置
  全局参数配置
业务
  动作1
  动作2
测试
  测试_动作1
  测试_动作2
主流程
```

“配置、业务、测试”是分组，其下是流程；“主流程”位于根级。`动作1/动作2` 是结构示例，实际名称描述具体业务，例如“打开售罄看板”和“测试_打开售罄看板”。

- 对话框配置收集和校验交互输入；全局参数配置管理共享参数和默认值。
- 业务流程各自完成明确动作，便于主流程组合调用。
- 测试流程调用对应业务流程并验证结果，避免复制一套独立业务逻辑；主流程正常运行不自动执行测试流程。
- 主流程负责调用配置、编排业务和处理结果。引擎的 `main` 身份和启动流程关系保持不变；不要为了显示“主流程”而改写其 `flow_id` 或尝试重命名不可改名的主流程。
- 修复已有应用时，只调整本次涉及的流程；不因新增规范顺带拆分、迁移整个应用。小任务也不创建没有用途的空流程。

分组写入前先查当前工具能力。当前已核验的 `flow create`、`app.create_flow` 没有分组字段；不要猜 `--group`、`group_name`，也不要用带斜杠的流程名模拟分组或直接修改应用目录。工具无法写入分组时记录组织方案和“分组未写入”，继续完成支持的开发工作，不能声称已建立真实分组。

## 网页实现方式

网页元素优先直接使用经过当前页面验证的 XPath，尽量避免影刀元素捕获及自动生成的样式类链。具体实现见 [VisualFlow](visualflow.md)、[CodeFlow](codeflow.md)；XPath 的验证和作用域见 [浏览器指南](browser.md)。

元素库用于已明确需要保留的既有资产、专用表格能力，或当前 SDK 无法直接用 XPath 表达的已确认场景。iframe、Shadow DOM 等场景先核对能力，不能假定普通 XPath 能跨越上下文。

失效修复不能直接删除仍有业务场景使用的旧定位。保留经过验证仍有效的新旧候选，并按 [维护指南](web-maintenance.md) 消除共存歧义、验证每次只操作一个正确目标。
