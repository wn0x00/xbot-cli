# 相似元素集合修复与兼容验证

用于 `collection/collection_then_single`、父子相对 XPath 依赖、新旧页面混用。修复对象是“业务集合契约 + 相关定位 + 行为验收”。原来的单元素 ROBULA+/加权 helper 保持独立，不把集合缩成一个唯一节点。

本文件属于 Web 模块；进入前按 [平台识别与模块选择](automation-routing.md) 核实实际失败调用，不把 Windows 列表或 XML 形式的原生树交给此解析器。

## 从故障到可修复性

1. 读取原错误、run_id、具体调用点、原流程及真实被调子流程。区分查找零匹配、子字段零匹配、未就绪、登录权限、网络、业务拒绝及动作结果未知。集合查询返回空列表也可能导致流程静默跳过，不一定有 SDK 异常。
2. AI 根据上下游代码反推契约，逐项提供源码原文/行号、历史事实、推断及待验证项。输入参见 [collection-analysis.json](../templates/collection-analysis.json)。原 XPath 的字面含义与目标业务含义分开描述；不能用当前候选反造历史基线。
3. 确认集合区域、成员业务键、字段读取、过滤/排序/遍历语义、允许空集规则及独立完整性来源。分支中出现的名称不是完整白名单，历史数量不是永久数量；分页和虚拟列表必须取得页面外的完整性证据或明确逐页协议。
4. 确认可修复性。可修复须能重新确认对象、定位变化根因和验证方案；不确定或不可修复时只出报告，不改业务代码或旧资产。
5. 在授权测试环境新建或复用解析子流程及验收流程，先验证候选和兼容行为；可修复时再做最小修改、回读、静态检查及运行验收。不要通过重跑有业务副作用的整条流程诊断。

AI 输出还必须包含 `dependent_locators`：父相对字段、点击后的关联面板、共享引用分别记录。只有能证明存在父子数据流的相对查询才联动修复，不按 `./` 前缀全局替换。

## 候选生成与父子联动

用语义契约找到当前页面中的真实候选组，算法依据真实 DOM 属性、文本和结构生成路径。ROBULA+ / 加权生成器用于已确认的唯一锚点；ROBULA+ 不直接生成完整集合规则，也不负责恢复业务含义。重复成员规则单独合成并验证，不让 AI 从描述直接拼最终 XPath。

确定父集合后，逐成员检查每个旧子定位的唯一性、读取值和含义；仍有效则保留。确实失效时新增子版本，再验证旧/新父与旧/新子的实际组合。仅标签或 class 看起来相似不能视为正确。

可用 [collection-compat.py](../scripts/collection-compat.py) 做普通 DOM 的只读兼容解析参考。`attribute_locator()` 为已经确认的属性和值生成带正确引号的 XPath；它不发现目标、证明属性稳定性或推断业务。`resolve_collection()` 不点击、不改代码、不写元素库；`COLLECTION_RESOLVED` 表示当前契约可解析，仍需行为验收与写入前复核。

### 解析器输入

由 Agent 在读取源码/真实页面证据后构造字典：

- `schema_version:1`；分类 `collection/collection_then_single`；`uncertainties:[]` 只在真实缺口已解决时成立。
- `page`：origin、path、完整 query/fragment、页面 locator、记录/就绪等属性断言。
- `region`：唯一可见区域的 locator 与业务属性断言。
- `variants`：同时保留旧、新父定位，`kind:xpath` 从区域开始，`version` 记录来源。
- `merge_policy:same_region_union`：仅在已证明同一区域允许成员混合两版时使用。不能用它合并两个不同业务组。
- `coverage:{kind:exact_keys, keys:[...]}`：来自本次业务数据、可核验清单或真实历史不变量；不能从待修复的 DOM 结果自行复制。同一键存在多个可见 DOM 成员时停止。
- `member`：业务键属性、身份属性、是否要求启用、字段读取规则及旧/新字段定位。
- `selection`：`all` 按契约 keys 的明确业务顺序，或 `business_key` 选一个；位置选择须额外分析，本参考解析器拒绝。
- `allow_empty:true` 只在业务契约允许且独立完整性来源确认为空时设置。

locator 为 `{kind:"xpath",value:"...",version:"old"}`。查询层保留经当前引擎验证的工程 Selector 入口，但当前原子集合审计仅支持普通 XPath，Selector 集合返回 `ATOMIC_SELECTOR_PROFILE_UNSUPPORTED`；不得填标志绕过。普通 XPath 子路径需保持成员范围；参考实现保守拒绝父轴、其他轴和 union，不接受跨上下文的字符串拼接。

### 旧新兼容决策

| 当前页面观测 | 决策 |
|---|---|
| 只有旧版或只有新版 | 验证完整成员及字段后使用；另一版本仍保留 |
| 两版命中同一批实际 DOM 节点 | 按当前文档代次与节点身份去重，每个业务成员只处理一次 |
| 同一区域有旧版 A、新版 B/C | 仅在声明并验证混合成员协议后合并，再验收完整性 |
| 旧隐藏、新可见 | 排除隐藏副本；不能将禁用目标当隐藏副本绕过 |
| 同业务键有两个不同可见节点 | 停止，补版本/区域消歧条件；不取第一项 |
| 字段旧/新命中同一节点 | 去重后读取 |
| 字段旧/新命中不同节点 | 停止；不能选一个值更像预期的节点 |
| 某成员字段缺失/值异常，或成员漏取/误入 | 停止，不跳过该成员伪造完整集合 |
| 动作已执行或结果未知 | 不切换候选重放；查询结果/对账后处理 |

`resolve_collection(browser, contract, budget_seconds=12)` 返回内部成员句柄及公开证据。`public_result()` 去掉不可跨 Flow 传递的句柄。执行前调用 `revalidate_collection()`，用重新获得的句柄；导航、契约、成员身份或字段变化使原结果作废。业务代码每次动作仍须按站点契约验证可操作性、遮挡和结果，不能把解析结果当动作授权。

## 密集业务页面的采用门槛

业务修复使用 `validation_profile:"business"`。省略该字段的兼容模式仅证明结构可解析，不能凭 `COLLECTION_RESOLVED` 自动采用补丁。页面元素很多时，最危险的是另一区域也具有相同键和相似结构，不是 XPath 是否唯一。

除基础契约外，business 模式要求：

- `coverage.source` 记录独立清单来源；`member.expected_by_key` 按每个业务键提供全部字段的预期值。来源应是本次输入、可靠业务接口、核验过的台账或历史业务合同，不能复制候选 DOM 来让它自证。脚本只能检查声明是否完整，无法认证来源真实性。
- `member.identity_fields` 指明可区分对象的字段，例如租户、账期、名称、动作；字段通过既有相对 XPath 读取。`expected_by_key` 必须覆盖所有读取字段，而不只是全局 `allowed_values`。同属允许名称集合的两条记录互换名称也要拒绝。
- 页面和区域均有身份属性断言。断言的业务强度由源码、历史事实及独立数据确认，不能把随意添加的标志当作业务身份。
- 仅在原流程确实需要点击时，`member.action_field` 指明真正的动作节点字段，`member.action` 声明 `kind:"click"`、经过确认的 `tag` 或 `role`、需要检查的 `attributes` 以及 `prior_outcome:"not_attempted"/"confirmed_not_applied"`。非动作字段不能冒充按钮；结果未知或已执行不得进入预检。调用 `validate_business_action()` 前由流程准备视口；它不滚动、不点击。字段与动作必须来自已经确认的同一成员。这些调用方声明不能代替业务绑定证据或对账。

纯读取集合使用上述独立清单、逐键字段及作用域要求，通过 `resolve_collection()`/`revalidate_collection()` 检查；不要求 `action_field/action`，不调用点击预检，也不能为通过检查虚构点击用途。读取结果须另与独立数据核验；`COLLECTION_RESOLVED` 仍不等于补丁可自动采用。当前动作预检只实现点击，其他动作类型另行验证。

有写入后果的操作还须确认显示业务键与后端对象、动作的绑定，例如经过核验的详情 href、表单主键或记录 ID，并将可观测标识纳入逐键字段基线。名称、显示编号和按钮文案全部一致仍可能操作另一后台对象。若绑定藏在不可核验的事件处理器中，先停在只读提议，不能凭显示字段通过而执行。调用方每次动作后更新执行结果；`prior_outcome` 不是自动消费的一次性许可。

解析在一次 DOM 任务内读取全部版本、成员、子字段和身份，再将原生句柄逐版本核对，并再次原子读取语义快照。密集页面使用缓存的父子索引，避免反复遍历长表格的前序兄弟；字段读取也避免逐字段跨 SDK 往返。该方法降低撕裂观测风险，不构成浏览器与后续点击的事务。

动作预检重新解析后，在同一 DOM 任务中比对语义快照、所属成员、动作节点、禁用状态、祖先可见状态和中心点命中。被遮挡、指针事件禁用、处于视口外或状态变化均拒绝。`BUSINESS_ACTION_READY` 是即时观测，调用方仍须确认动作授权并验证结果；点击报错或结果未知不能换 XPath 重放。

`screen_collection_candidates(browser, baseline, candidates, budget_seconds=30)` 可验证多个候选区域。候选格式为 `{name, region_locator}`；用 `attribute_locator()` 或已确认锚点的 ROBULA+/加权结果生成路径。候选只能改变定位，不能覆盖业务身份、完整性清单或字段预期。每组运行相同 business 合同；同一实际区域可合并等价路径。两个不同区域都满足完整合同则返回 `CANDIDATES_AMBIGUOUS`，不按相似度、短路径、新版或位置选一个。`CANDIDATE_VALIDATED` 仍只是候选验证结果，不执行写入。

候选批次末尾再次验证唯一获选组；若期间页面改变则返回 `CANDIDATE_STALE`。批次中底层 XPath/SDK 错误直接暴露，不当作“该候选不存在”继续采用另一个。真正写入和动作前还须复核；原子读取后、点击前的间隙始终存在。

密集页验收必须同时记录 DOM 规模、匹配候选数和目标规模。增加无关节点只能测试负载；还必须加入同键错误租户/账期、同名不同动作、可见镜像区域、字段互换、隐藏字段、嵌套项、分页缺项和预检后的变化。点击回执应由独立业务对象产生，不能只看修复 XPath 再读到的文本。将误接受、误拒绝、正确拒绝、正确修复和已知缺口分别统计；“按预期拒绝”不能写成“已自动修复”。

## 测试与写入

测试至少包括旧版、新版、两版同节点、隐藏副本、不同可见重复对象、混合成员、均无匹配、父变子不变、父子同时变化、字段缺失/多匹配、漏成员/误入、数据键筛选、页面未就绪、登录权限、动作结果未知，以及点击后的业务效果。通过包含“正确阻止”，不代表所有场景都能自动修复。

可用新建 CodeFlow 承载本脚本，其 `main(args)` 仅提供 In `page_url/contract_json`、Out `result_json` 的隔离只读探测；浏览器模式需要按证据适配。它的 Python helper 可供本应用测试模块复用。真正跨 Flow 业务调用继续使用显式 In/Out 合同，不能传 WebElement。

只有完整证据支持可修复时，修改已确认的调用点，引入旧/新判断和依赖字段配置，而非把旧 XPath 常量替成新常量。旧资产当前错误命中时可保留历史但停止执行。写入前回读源码、参数和资产版本；写入后回读、检查和运行。子流程测试失败不得继续业务补丁，不自动发布或推送。

报告必须包含：根因和报错位置、XPath 字面含义与业务契约、判断结果、旧新保留策略、改动范围、尝试过的方法、每场景预期/实际/动作数、业务回执、run_id、未覆盖范围及下一步建议。不可修复或不确定也要报告。

## 当前能力边界

- 是普通 DOM、显式独立键清单契约的参考解析器，不是通用 AI 自动修复服务或生产应用自动补丁器；用途 receipt、源码摘要、共享引用和资产版本仍由协调 Agent 在写入前核验。
- business 模式要求逐键逐字段基线，适用于能取得独立业务数据的页面；缺少基线时不降级成结构匹配后自动修复。`coverage.source` 和 `identity_fields` 为调用方声明，无法自行证明语义或数据可信性。
- 全字段精确基线可能因正常业务状态更新而拒绝。应从独立业务来源更新合同后重新产生提议，不能把候选 DOM 当前值抄回合同消除报错。就绪、登录及权限守卫应逐项有证据，非空属性字典不代表已覆盖这些状态。
- 若页面会同位置替换节点或复用虚拟行，且不能证明业务键与后端记录/动作绑定，也不能取得可靠渲染代次，则属于不确定：允许只读提议和隔离测试，不自动采用业务补丁或执行动作。脚本可能仍返回结构/语义通过，协调 Agent 不能把此结果提升为业务授权。`replace-same` 必须在保持视口和业务字段不变的条件下单独验收，不能拿别的拒绝原因冒充替换检测。
- 原单元素 ROBULA+ helper 未改；集合侧尚无自动发现重复祖先、完整跨函数数据流或通用网站适配器。
- SDK 查询异常直接暴露，不能当作“旧版无匹配”切换新版。预算在步骤间检查；单次底层 SDK 卡住并非硬实时终止。
- DOM 身份基于当前文档代次和根内路径；结构模式查询内部禁止路径碰撞并核对原子身份清单，business 模式比对两次完整语义快照与句柄清单。它不是持久业务标识。页面守卫、区域和成员检查文档与包含关系；嵌套成员默认拒绝，防止父项借用子项字段。相同内容替换可能无法区分，尤其 SDK 会按原定位重新解析 WebElement 时；旧句柄复核仅为尽力检查，不能声称稳定节点 ID。DOM 复核与动作之间仍有竞态，需要站点级渲染代次、可靠对象标识或事务/幂等协议。
- 可见与启用不等于无遮挡、可安全提交；动作前可操作性和授权边界仍执行原 [规程](locator-repair.md)。
- 原始 XPath 不跨 iframe/ShadowRoot；分段协议交给影刀 Selector 引擎。此解析器对 ShadowRoot 内部 DOM 身份明确拒绝；没有集合专用原生验收前，不宣称已支持复杂上下文自动集合修复。
- 虚拟列表/分页全量、未知成员键、封装动态查询、来源不明的候选和有未知副作用的动作，保持不确定并停止修改。
