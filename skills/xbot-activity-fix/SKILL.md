# 影刀指令维护与修复

依据真实故障版本、入口、输入和业务状态恢复预期行为。命令查 [xbot-cli-doc](../xbot-cli-doc/SKILL.md)，补丁涉及参数、代码或公开契约时只读 [开发规范](../xbot-activity-dev/SKILL.md) 的相关部分，不因报错直接重写指令。

<a id="tasks"></a>
## 先安排维护任务，再操作

开始时依据任务模式和下表建立**本次可执行任务清单**，给每个故障/入口安排步骤、状态及完成证据，再推进。优先使用实际可用的计划/待办工具，无工具时在对话中维护，不默认新增任务 Markdown。清单不是新增审批，已授权的维护连续做到验证收尾，不只列计划或修完源码就结束。

| 阶段 | 要安排的任务 | 完成依据 |
| --- | --- | --- |
| F1 范围与现场 | 确认维护模式、目标 app/flow、故障版本与当前编辑/发布/安装版，记录原错误、运行 ID、预期/实际 | 目标与范围清单、日志位置、已知条件和缺口 |
| F2 原调用与前置 | 读取真实入口、输入消费、调用链、对象来源和提前退出；配置任务定位真实字段 | 调用/字段映射；账号、页面/窗口、记录等前置证据 |
| F3 复现与根因 | 按模式复现或只读分析；配置问题核对旧新值和保存链路，判断根因与可修复性 | 同故障证据、确定性静态依据或配置差异；未复现与未知明确记录 |
| F4 备份与最小修复 | 可修改模式下保留可恢复原文，回读写前基线，生成并实施最小补丁 | 备份、实际 diff/回读、兼容和共享引用影响 |
| F5 验证与持久化 | 按模式核对静态、原入口运行、业务结果及受影响旧调用；元数据改动核验展示、真实保存和完整重开 | 各检查面结果、执行 ID/业务回执或配置与重开证据 |
| F6 临时恢复与状态 | 等安全终态后恢复临时参数/函数/接线，只清理本任务资源，检查残留及未知动作 | 恢复回读、残留清单、必要的只读对账结果 |
| F7 交付核对 | 逐项核对清单，报告根因、改动、实际验证、剩余问题和使用方版本 | 最终任务状态与证据；保存/同步/发布分别说明 |

状态用“待处理、进行中、已完成、失败、受阻、不适用”，每项附结果或证据。完成/失败、范围调整和切换方案时及时更新；新增受影响入口和回归项补入清单，不静默删掉失败任务。续接先查清单与原 run_id/task_id，避免重复动作。

F1–F7 用来检查覆盖，不要求每次列七条。按“目标 → 具体动作 → 阶段 → 状态 → 证据/缺口”安排，小改动可合并展示；多个故障/入口或独立失败项分别安排。下面是“仅将 read_account.account_name 的 label 改为账户名称”的初始清单示例：

| 具体任务 | 覆盖阶段 | 初始状态与预期证据 |
| --- | --- | --- |
| 确认工程、版本和 function/name 对应的原 label，备份负责文件 | F1–F3 | 待处理；唯一字段映射、旧新值和原文；业务复现不适用（纯文案） |
| 只改指定 label，回读并比较参数名、类型、默认值和注册 | F4 | 待处理；精确 diff；无关改动为零 |
| 查看实际展示，真实保存并完整关闭重开回读 | F5 | 待处理；UI 与持久化结果；无客户端时为受阻，业务运行不适用 |
| 核对临时改动、清单与交付结论 | F6–F7 | 待处理；无临时项则说明无须恢复；报告实际完成层次 |

代码故障将相应任务换成“定位原调用及有效输入 → 最小补丁 → 静态/原入口/业务核验 → 恢复收尾”；只读任务保留调查与结论，修改项不适用。不要为合并清单省略必需验证，也不要为凑阶段触发业务。

只读、仅复现、仅验证不包含的修改或运行项标“不适用”并注明范围；完整维护中确实需要却缺环境/账号/证据的步骤标“受阻”，不能用静态或辅助成功替代。配置维护无需运行真实业务，F3/F5 安排字段、展示和持久化检查。交付前必需项未完成时明确交付调查结论/候选及缺口，不报告完整修复成功；也不为清单打勾扩大业务或发布范围。

| 请求范围 | 执行边界 |
| --- | --- |
| 只读调查 | 读取与分析，不运行或改业务 |
| 仅复现 | 重建获准条件，运行原实现；不改正式业务逻辑 |
| 完整维护 | 连续调查、最小修复、验证和收尾，不逐步重复询问 |
| 仅验证 | 检验指定候选，不顺手修复或重构 |

正常 save、sync 关闭与 open 重开可直接完成。sync 本身不改指令逻辑、参数、开关或归组，不影响指令正常使用；无需额外同步确认。发布及真实业务写动作仍按具体任务范围执行。

## 诊断与修复判断

未知项保留未知并推进可做的分析，本机结果不能冒充用户故障环境。先从代码推导“动作 → 对象/输入 → 前置状态 → 证据”；目标本来不应出现、没登录或未就绪时解决前置，不直接改定位。

先做有效尝试，间歇问题才按假设、用户预算和停止条件有限续试，没有固定通用三次规则。缺输入、未到失败路径、另一错误、本次条件未复现分别记录；超时/unknown 续查原运行与业务结果，不启动第二份。

原故障复现且根因明确，或有精确的确定性静态缺陷依据时，才在维护范围内修复；后者须明确未动态复现。仅错误文字相同、候选相似或当前版单次成功不能证明根因。写前回读合并漂移，保留旧契约及他人编辑。

## 环境、备份与临时条件

已有资产 ID 优先客户端读取，不先全盘找源码。按需记录 CLI、运行客户端、实际后端/provider、目标环境、脱敏账号及业务对象；后端目录不能反推客户端版本。app_id/expect-app 是工程身份，URL/frame/记录键或程序/窗口是业务身份，分别确认。

路径不可用时可映射到任务新目录，但保留触发缺陷的扩展名、编码、大小、权限、表结构、空值和路径字符，并说明差异；固定路径本身触发问题时不能静默换掉。没有读到文件不推定内容。

修改前把源码、块/form、In/Out、注册/接线等受影响原文与关系备份到工程外，记录身份、版本、时间和恢复通道；hash/快照不能恢复原文。小修留精确原文/diff，多文件留相关文件；需要 Git 时在外部备份使用，不在运行中的应用目录初始化仓库，不自动提交推送。

运行输入优先用现场支持接口，不能传参才按授权暂改参数或 test 辅助。样例与正式默认值分开，辅助必须调用同一业务实现；普通应用可临时接线但不注册成正式测试入口。写后回读并证明消费路径，不用手工 UI 成功代替原 Flow 复现。

原运行到安全终态后，仅恢复本任务临时值/函数/接线，保留正式补丁和同期修改；回读一致才记 restored，失败/不明记录残留。只清理本任务资源，不清会话或关闭无关窗口。配置恢复不会撤销已发生业务动作，unknown 时不热改或自动回滚。

## 元素故障分流

读取实际失败 API/块、接收对象与来源，跟进封装和当前分支；按证据选择平台，不按 XPath 字符串、exe 外壳、变量名、当前活动窗口或空快照猜。

| 证据 | 处理 |
| --- | --- |
| 已核实网页对象访问 DOM/XPath/frame/Shadow | 读 [Web 修复](references/web-repair.md)，再分单元素与集合 |
| 已核实原生窗口/控件/UIA 调用 | 读 [Windows 修复](references/windows-repair.md)；原生文件弹窗也走这里 |
| Electron/WebView 中 DOM 调用 | 仍走 Web；同程序原生菜单另走 Windows |
| 对象动态、分支不明、资料冲突 | 保留 unknown，补调用链和 schema，不为探测平台重跑动作 |

CLI 可辅助观察或准备条件，报告区分辅助诊断、模块测试和原调用完整复现。影刀窗口只有在原流程操作影刀自身时才是业务目标。Web 用途 AST 信号不证明接收对象平台；UIA 资产不交给 Web 修复器。

## 文案、启用禁用与分组维护

配置任务无需先执行业务复现。先确认实际位置、版本与旧新值并备份；有客户端操作就使用实际能力。需改文件时按 [元数据共同流程](../xbot-activity-dev/references/metadata.md#closed-edit) 关闭后最小修改，再核验真实保存、展示和完整重开。字段与检查器也集中在该参考，避免维护两套步骤。

| 任务 | 方法与步骤 |
| --- | --- |
| 标题、label、说明、业务展示、指令/动作描述 | F2 区分实际显示位置并按 function/name 找原型/参数 → F4 按 [文案步骤](../xbot-activity-dev/references/metadata.md#text) 改负责字段和模板 → F5 核对普通/空/变量值展示、保存重开；不改内部参数名或枚举 value |
| 启用/禁用 | F2 明确目标和四层现状 → F4 按 [开关步骤](../xbot-activity-dev/references/metadata.md#enable) 操作眼睛，或关闭后同步维护 opened/hidden/Python/XML → F5 检查完整集合、绑定与重开；保留必要内部依赖 |
| 创建/改名分组、调整模块 | F2 读全量组与归属 → F4 按 [分组步骤](../xbot-activity-dev/references/metadata.md#groups) 先建组再移动、改名同步全量引用、零引用再删除 → F5 核对模块未丢失/误移及重开；category 分类单独检查 |

| 未生效/漂移 | 先排查 |
| --- | --- |
| 字段改了，界面仍旧/占位符原样显示 | 正确应用与原型、真实负责字段、模板语法与内部参数名、真实保存、是否查看旧安装版 |
| 眼睛开了，公开指令仍缺失 | hidden、Python/XML 集合、namespace、function/签名和消费者安装版；页签及块启停不算公开开关 |
| 保存/重开后恢复旧状态 | 是否热改过文件、实际保存生成路径；保留前后 diff，不每次保存后补文件或改 openedFlows 掩盖 |
| 组出现但模块没进去/多出组 | groupName 精确引用、目标 filename、改名是否更新全量引用；不删含成员组解决 |
| 本地正常，使用方仍旧 | 发布/安装版本及实际引用来源，按任务范围处理升级 |

弃用兼容继续保留注册，独立隐藏必须证明版本支持；关闭眼睛可能注销旧调用。用户明确指定的启用/禁用范围直接执行，不因旧入口未进新推荐清单自动禁用。

## 操作规范与交付

不吞异常、删除失败步骤、硬编码本次记录、取首匹配或无限重试掩盖故障。旧新定位在动作前查找并按实际对象去重，唯一业务目标确认后执行一次；动作已发出或结果未知先对账，不切定位、通道或运行 ID 重做。共享资产保留有效历史并仅修改已确认引用。

按改动选正常、边界、拒绝、兼容和未知结果用例；静态、模拟、辅助测试不能替代原入口和独立业务回执。缺必要条件时交付证据和具体下一步，不猜补业务。F7 对照任务清单逐项收尾，报告直接用下表，无需新增维护报告模板文件：

| 项目 | 内容 |
| --- | --- |
| 范围与现场 | 资产/版本/环境、原入口与输入、预期/实际、失败位置、已获任务范围 |
| 根因 | 直接证据、推断与缺口；动态已复现/未复现/未到路径/静态确定分别说明 |
| 改动 | 受影响文件/块/参数、兼容影响、可恢复备份、正式补丁与临时差异 |
| 验证 | 写入回读、静态、原运行 ID/终态、Out、独立业务结果、动作次数、未执行项 |
| 收尾 | 临时恢复与残留、元数据保存重开、发布/安装/使用方状态、下一步 |

每项分别记通过、失败、未执行、受阻或未知。本地修好、已保存/同步、已发布、使用方已恢复分别给证据。helper 仅按需运行，不是常驻自动恢复服务；缺配套资料时继续独立调查，写入前须补可靠契约。
