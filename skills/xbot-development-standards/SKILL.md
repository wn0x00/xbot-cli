# 影刀开发规范

规范影刀指令集与应用的开发和交付。指令集应可被业务人员直接配置、结果可验证、已有流程调用保持兼容；普通应用按独立差异约定组织主流程和业务模块，而不只是交付能运行的 Python 函数。

## 与应用开发的边界

本 skill 主体用于指令集开发，不把指令启用、公开注册、描述面板和测试函数规范套到普通应用。普通应用按[应用开发差异](references/application-development.md)处理：从主流程进入主运行模块的 `main(args)`，不设置测试入口或测试函数；复用功能拆入 `utils`，由正常主流程完成运行核验。实际应用开发可配合 `$xbot-app-dev`，不以本 skill 的四层公开集合检查器验收普通应用。

## 开始前

先读工作区约定和当前应用现状。记录目标应用身份、引擎版本、源码、In/Out、原型、分组及启用状态，保存可恢复的修改前副本。维护时以客户端回读的当前源码为准，不能用旧的本地副本覆盖已修复逻辑。

默认通过当前环境提供的 `xbot-cli` 与客户端交互；有 `xbot-app-dev` 时配合其工具契约。先查 status、帮助和 schema，再操作，不凭记忆编造参数。Studio 操作使用显式应用断言，应用 ID 不能替代业务窗口或账户身份。

用户要求先确认清单时，先给出“指令、合并来源、中文参数、示例、输出、副作用”表，确认后再实现。既有测试授权只在其指定对象、动作及范围内有效。

## 按修改内容读取

- 设计或改动输入输出、中文说明、编辑器、默认值：读 [契约与参数界面](references/contract-ui.md)。
- 改动指令函数、入口、批处理、依赖或界面自动化：读 [代码与执行](references/code-execution.md)。
- 修改源码之外的 label、描述、占位符、分组、启用状态，排查发布后开关不符，或准备交付：读 [元数据与交付](references/metadata-delivery.md)。先区分弃用兼容、仅隐藏兼容与完全注销，不把关闭眼睛当成只隐藏。直接维护配置采用关闭设计器、修改四层、正常打开、真实保存并再次关闭重开核验；不进行内存修改或热更新验收。`sync` 有同步副作用，不能当作无上传的关闭命令。
- 验收或排查“最后一步未执行”“已生效但报错”等问题：读 [测试与验收](references/acceptance.md)。
- Flow 转 Code 时结合独立技能 `$xbot-flow-to-code`，使用其中的中文代码规范、测试模板、全量SDK转换目录与语义对照；已有参数和原 Flow 开关仍须保持兼容。

## 不可混淆的边界

1. 英文 `snake_case` 用于内部标识和新 In/Out；中文用于标题、label、说明和业务展示。已有参数名及命名空间不得无授权重命名。
2. 正式执行入口必须执行其声明的业务动作。预览、只检查路径、离线模拟必须显式独立，不得返回“执行成功”。测试函数不另写一套动作实现。
3. 写入成功、静态通过、运行完成、业务结果确认是不同状态。发出点击不等于提交，接口返回不等于业务回执。
4. 动作可能已生效后，只补核验，不自动再次发送或提交。批次失败需要保留已完成项、当前项和结果未知状态。
5. 不让业务人员填写运行时内部目录、库文件位置、分片或内部编号。上游记录应通过变量传递，并说明如何取得。
6. 不能把当前客户端版本的一次实验结果写成平台通用能力。数据源、缓存、同步和跨版本限制须如实说明。
7. 指令集的测试样例参数值仅写在 `test_*` 测试函数内；`main(args)` 直接从 `args` 取参，不补默认值。正式默认值在流程参数中配置，详见[参数读取与默认值](references/code-execution.md#参数读取与默认值)。普通应用不设置测试函数。

## 完成标准

契约、源码、参数面板、原型展示与启用清单相符；测试和辅助模块不暴露为业务指令；实际回读确认分组、中文文案、占位符及默认值；必要的运行验收有证据；未验证路径单独列出。配置维护按关闭重开流程完成持久化验收，不以 `app.reload` 代替，也不擅自发布、同步或提交版本。

## 统一检查与证据

使用[只读检查入口](references/metadata-checker.md)和[策略清单模板](assets/metadata-policy.example.json)核对四层集合、绑定、参数、默认值、分组、保护快照及读期间变化。按[统一报告模板](assets/acceptance-report.md)分别填写静态、旧消费者、真实保存、完整重开和发布证据；脚本未发现问题不代表完整验收。当前适配范围和未检查项必须随报告交付。

仅排查特定版本故障时读取[版本限制与历史证据](references/version-evidence.md)，不从历史应用数量、描述回写或强制打开回执推导通用平台能力。
