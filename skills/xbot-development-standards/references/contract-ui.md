# 契约与参数界面

## 业务边界和合并

先明确操作对象、输入来源、输出去向、成功条件、失败条件和副作用。一个指令对应可理解的业务动作；共同对象、权限、返回结构和操作路径相近时可合并，用少量下拉项区分。不要为了减少数量把互不相干的操作塞入一个巨型指令。

合并前检查已有调用。不能把“弃用”“不再展示”“注销注册”当成同一操作，也不能承诺当前版本尚未验证的隐藏兼容能力。新增可选参数应有向后兼容默认值。删除或变更输出类型属于破坏性变更，须明确迁移方式。

### 旧入口的三种策略

| 意图 | 必须保留或改变的内容 | 必须独立验证的内容 |
| --- | --- | --- |
| 弃用但保持兼容 | 保留原命名空间、函数绑定、注册、参数、默认值、输出与异常语义；可标注已弃用并推荐新入口，不默认关眼睛 | 使用原配置的旧流程仍可解析调用；对照参数、默认值、输出和失败行为；保存及完整重开后注册不漂移 |
| 隐藏展示但保持兼容 | 可发现性与可调用性分别处理；只有当前版本存在独立展示机制且验证后才能隐藏，仍保留旧调用所需注册 | 新用户界面确实不展示；旧消费者仍可加载和调用；真实保存、重开及授权发布/安装后两种性质同时成立 |
| 完全注销公开入口 | 破坏性变更；先获得明确授权并确认旧消费者迁移/退役，再移除公开注册；内部源码是否保留另行决定 | 旧引用清点和迁移证据、四层注销结果、替代入口可用、内部依赖不受损；不得再声称旧入口兼容 |

本机已验证的小眼睛关闭会同时移除 Python/XML 公开注册，属于公开入口禁用，不是“仅隐藏”。保留源码或内部 `process.run` 可运行，不能证明旧的外部 `xbot_extensions` 调用仍兼容。当前版本若不支持独立隐藏，保守方案是继续注册和展示、标注弃用；不要尝试 `opened=false` 后手留包装函数来假装兼容。

上述运行或发布验收仍受当前授权范围限制。未获授权时做静态契约对照并明确记为“旧消费者运行未验证”，不为验证兼容自动重放有副作用的旧流程。具体字段与写入前置条件见[元数据与交付](metadata-delivery.md)。

## 命名和结构

| 内容 | 规则 |
| --- | --- |
| 指令标识、参数、函数、变量 | 新增使用英文 `snake_case`，不加前后空格 |
| 指令标题 | 中文动宾结构，说明对象和动作 |
| 参数 label | 中文业务名，不把实现名原样展示 |
| 指令描述 | 说明真实动作、范围、关键条件和副作用 |
| 动作描述 | 用当前平台已验证的变量占位语法表达本次动作 |
| 输出 | 同一动作保持类型稳定，空列表不伪装失败，未知不伪装空数据 |

区分“缺失、空串、空列表、零、否、未知”。必填应与运行时校验一致；条件必填在说明和代码中都要体现。记录类型要接受对象变量，不要求用户手填 JSON。单条记录与记录列表用不同 label 和错误提示。

正式默认值在流程 In 参数中设置，原型与之保持一致；测试样例值只写在测试函数内，`main` 不再设置兜底默认值。具体取参方式见[参数读取与默认值](code-execution.md#参数读取与默认值)。

## 编辑器选择

- 固定枚举使用下拉项，展示中文、内部值稳定；说明各选项的实际效果和变量可传值。
- 二元设置使用复选框；整数用数值输入并说明范围、单位和边界。
- 多对象使用列表，支持列表变量，不使用难以转义的逗号分隔文本。
- 文件输入使用当前平台已验证的文件编辑器或路径列表，不把目录当文件。
- 输出目录仅在业务确实需要用户指定保存位置时提供，优先可选并自动生成不覆盖的文件名；运行时缓存路径由程序管理。
- 高级参数只放低频技术调节项。说明其适用场景、默认值及无效条件，不把业务必填参数藏进去。

不要凭编辑器名称推测平台支持情况。先查看同应用有效参数、schema 或 SDK 文档，再配置。记录选择器、时间控件和文件选择器在不同版本可能不同。

## 参数说明清单

每项至少说明格式或类型、业务含义、一个适当示例、默认值/空值含义；按需补充：

- 上游来源：先运行哪类读取指令，选择哪个输出列表中的单项或循环当前项。
- 多对象：元素含义、允许重复与否、处理顺序、重名时如何消歧。
- 操作类型：每项是否创建、修改、解除关联或删除；不能只写“选择操作类型”。
- 条件生效：例如仅在某操作模式生效，不适用时是忽略还是明确拒绝。
- 时间：时区、格式、包含边界与否、单端留空含义、本地同步/服务端范围。
- 数量：默认值、上限、时间模式是否覆盖数量；如果声明不限条数，代码不得仍套用有限窗口。
- 文件：输出是否原始文件、缩略图、截图或转码；不能换扩展名冒充格式。

参数互斥时优先拒绝冲突值并说明，不静默忽略用户可能以为会生效的内容。原有契约明示“忽略”的条件除外，且两端行为必须一致。

## 输出面向业务

保留完整可继续操作的原始记录；有复杂内部字段时可另给简明列表。时间戳提供固定时区可读格式，同时保留原始字段；确实缺失时不使用当前时间填充。

业务名称与内部身份分开。记录中可封装账户、对象、稳定身份和校验信息，供下游验证；不让用户在配置面板抄这些内部字段。名称重名、记录过期或归属不符应停止而不是猜测。

部分完成时输出已确认明细或将其挂在结构化异常中。不要把失败项塞进成功列表，也不要仅抛一句“失败”丢弃已生效信息。
