# 版本限制与历史证据

仅供解释当前保守策略和排查同类版本问题，不是操作步骤，不提供新的授权，也不代表所有版本均有同样行为。

## 样本范围

- 日期：2026-11-04。
- 客户端：本机 ShadowBot 6.3.39；部分批次配合 xbot-cli 0.9.1。
- 应用：本次“拼多多数据获取--副本”样本；业务名单以当前用户要求为准，历史数量不得复制到其他应用。
- 当时保存的备份、哈希与观察记录构成样本证据；本 skill 未附带可跨机器复核的完整日志，不能把下表当作当前应用的验收结果。

## 观察与决策

| 当时的观察 | 能支持的结论及限制 |
| --- | --- |
| 用户关闭主流程眼睛并保存：`opened` 变 `false`、`hidden` 变 `true`、Python/XML 移除公开入口；工作区页签未变 | 眼睛不是编辑页签开关；该路径是禁用公开注册，不能宣称只隐藏且兼容 |
| 完全退出后改配置、正常打开，再将原 description 按当前 `app.update_info` schema 原值写回，触发了保存和注册重建；无脏变更的 `app save` 不一定重建 | 需要真实生成及保存证据；原描述回写只是该版本已验证的触发方式，不是通用 API 保证，不得改成临时描述 |
| 随后 `app.reload` 再真实保存，公开集合漂移为119个编辑页签所对应的流程，注册含非法导入；刚 reload 后磁盘仍正确 | 必须检查下一次真实保存；该样本避开 reload，完整关闭重开，不修改 `openedFlows` 掩盖问题 |
| 前一批47个 Flow、63个 Python 模块及312个保护文件在重复保存、强制打开命令返回后保持稳定，但未独立记录关闭中间态 | 只是配置稳定证据，不能凭强制打开回执认定完整关闭重开 |
| 在明确同步授权下，原生 sync 关闭与独立 status 均确认设计器已关；关闭时补齐主流程四层注册，正常打开并保存后保持48个公开入口；再按备份恢复到47个，四层最终哈希一致，63个 Python 模块未公开、312个保护文件未变 | 支持该样本的关闭改文件、正常打开、真实保存方案；发生了授权同步，未发布或运行业务；数量不是规范 |
| 打开状态改文件后，普通无脏保存未覆盖磁盘；原描述回写触发真实保存后，主流程被内存旧值恢复禁用，四层回到原哈希 | 普通保存无变化不等于热更新成功；支持当前禁止打开状态直接改配置的前置条件 |
| 内存热更新未完成可复核验证，用户选择关闭重开 | 当前不执行内存探查、提升权限、修改活对象或通知；不能从静态可写属性推断运行能力 |

版本升级后，重新读取当前 schema、有效样本及实际持久化结果。历史方案的成功或失败都不能代替当前版本验证，也不能自动授权重做内存实验。
