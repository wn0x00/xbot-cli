# 元数据与交付

本文件只规定当前操作方式；特定客户端的实验、数量和限制集中在[版本限制与历史证据](version-evidence.md)，不能把历史样本名单或一次操作成功当成当前授权。

## 配置职责

| 配置层 | 职责 |
| --- | --- |
| CodeFlow 源码 | 业务函数、`main`、`args` 读写及相对导入 |
| `.dev/<filename>.flow.json` | 原流程 In/Out、类型、默认值表达式、方向和说明 |
| `prototype.block.json` | 标题、说明、动作模板、输入输出展示、编辑器、分类及可见性 |
| `package.json` | 应用身份、`flows`、`flow_groups`、`groupName`、`opened` |
| `__init__.py`、`prototype.activity.xml` | Python 公开入口及文档公开成员；不能拿磁盘源码存在替代注册存在 |
| `.dev/workspace.state.json` | 编辑页签、当前流程、断点和布局，不是指令启用清单 |
| 依赖与资源 | 应用虚拟环境、依赖版本及实际引用资源 |

源码 docstring 不自动成为面板 label；流程 description 不一定等于 tips。每项修改写到实际负责的层，再回读。源码和参数默认通过当前 CLI/Studio 接口维护；直接维护展示、分组或注册字段须有相应授权，不为这些字段操作编造 CLI flag。

JSON/XML 使用结构化解析；Python 注册使用 AST 或可靠解析器定位，保留必要导入、命名空间、ID、未知字段和无关成员。先读旧值、备份并记录哈希，写入前再查设计器状态及并发变化；不从零重建整个原型，不用模糊文本替换批量删入口。参数 upsert 后检查方向、名称、顺序及 ID；调用顺序与面板展示顺序分别按原约定保留，不强制二者相等。不能无条件保留第一项或最后一项去重。

## 注册、展示与弃用分开决策

先按[旧入口策略](contract-ui.md#旧入口的三种策略)确定意图，再填写[状态清单模板](../assets/metadata-policy.example.json)。当前已验证的眼睛开关映射为：

| 状态 | `flows[].opened` | 原型 `hidden` | Python/XML 公开注册 |
| --- | --- | --- | --- |
| 正常业务指令 | `true` | `false` | 均保留 |
| 弃用但保持兼容 | `true` | `false` | 均保留，原契约不变 |
| 完全注销或本来就是内部模块 | `false` | `true` | 不作为公开入口；必要内部源码/导入仍保留 |
| 仅隐藏且保持兼容 | 不预设通用映射 | 不预设通用映射 | 必须保留旧调用所需注册；没有独立展示能力证据时不执行 |

禁用眼睛不等于删除源码，但可能破坏外部调用。只有“完全注销”或确认从未公开的内部模块，才按关闭开关、移除公开注册的路径处理。注销旧业务入口还需要明确授权和消费者迁移/退役证据。重新启用则必须补齐有效注册，不能只把两个布尔值改回来。

仅隐藏不能套用本表的注销行，也不能因为启用名单里没列某个兼容入口就移除它。已验证版本不支持独立隐藏时，维持“弃用但保持兼容”，报告展示隐藏未实现。不同版本确有独立展示机制时，先记录版本、实际字段和消费者证据，再评审适配；当前只读检查器会把此模式列为待复核，不自动认可其运行能力。

按完整命名空间及真实 `function` 绑定匹配原型。`block.name` 可能用流程显示名称，而函数绑定使用 `filename`，二者不可混为一谈。缺失、重复、跨命名空间、绑定歧义时停止写入。测试、模型、工具等新辅助模块默认不公开，但不能借此注销旧的兼容入口。

## 分组与中文展示

按业务职责创建分组，先在 `flow_groups` 创建缺失组，再将流程 `groupName` 设置为精确组名；检查重名及悬空引用。不通过改流程 ID、名称中加斜杠来假装分组，也不强迫不同项目用固定中文组名。

逐项回读标题、说明、动作描述、输入输出 label/tips、required、editor、category 和下拉项。动作占位符采用当前版本已验证的语法，例如 `%item_name%`，只引用本指令已声明 In/Out；检查拼写、空格、残留引用、重复百分号和实际渲染。默认值与流程声明比较时，区分文本、表达式、缺失、空串、零、否和未知，不执行表达式来“核验”。

客户端常亮眼睛表示启用；禁用时点击常亮眼睛，启用时悬浮到该行再点击出现的眼睛。必须观察结果并保存回读，不能以“已点击”作为证据；点击无响应时停止盲目重试。

## 当前保存与重开流程

1. 记录应用身份、目标版本、当前状态清单和旧消费者范围，按[统一检查入口](metadata-checker.md)建立修改前快照。没有运行授权不运行业务；没有发布/同步授权不调用这些操作。
2. 保存当前工作，通过受支持方式完整关闭设计器，并独立回读 `studio.opened=false`。`studio current sync` 有同步副作用，仅在明确授权同步时可用；强制关闭须另获同意。普通 `app.reload`、`app open --force` 的回执不能替代关闭中间态。
3. 设计器关闭时备份四层文件并最小修改。弃用兼容入口保留注册；注销入口移除对应公开函数/XML成员；启用入口按当前版本有效样本补齐绑定、签名和 In/Out。没有可靠注册样本时由客户端生成，不猜造代码。写入前再次校验全部待写内容及四层文件的并发变化，失败时报告半套状态，不能覆盖用户同期修改来回滚。
4. 正常打开正确应用，回读 `studio.opened=true`，再触发真实保存。不能只相信无脏变更的保存回执；仅在已验证的版本和 schema 下使用客户端重建路径，具体版本例外见历史证据，不将描述回写等试验手段设为所有版本通用要求。
5. 只读核对：注册集合、可见集合、实际策略名单、分组、参数、默认值、绑定和保护文件。正常/弃用兼容入口要求四层一致；经版本验证的仅隐藏方案按其独立预期核对，不能要求可见集合必须等于注册集合。
6. 记录真实保存后的快照，再完整关闭、正常打开并真实保存，重复只读核验与稳定快照比较。记录关闭与打开状态、保存证据及时间；仅文件一致不能证明真的重开。发现漂移即停止报告成功，不在每次保存后补文件来掩盖故障，不更改工作区页签迁就开关。

当前不执行内存探查、权限提升、活对象/属性/通知修改或内存热更新验收。磁盘写入不能冒充客户端已更新；该路径只有历史失败证据，不是备选操作规范。重开失败时报告限制并保留差异，不退回内存修改。

## 发布及交付边界

最终回读应用身份、源码、In/Out 与默认值、中文展示、分组、注册、可见性及测试无动作默认阶段，避免下次运行自动重放测试写动作。

仅获授权时发布、安装并验证使用方指令中心和旧调用。开发态配置、安装版本和消费者缓存是不同证据；不盲目清缓存。未发布时明确写“本地持久化已验证/未验证，发布后可见性与兼容性未验证”。统一报告见[验收模板](../assets/acceptance-report.md)，检查器的静态结果不能填成真实运行结论。
