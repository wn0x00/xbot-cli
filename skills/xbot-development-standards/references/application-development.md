# 应用开发差异

本页记录本项目普通应用开发的约定，用于与指令集规则区分，不把某种项目组织方式宣称为所有影刀项目的强制结构。本 skill 主体仍用于指令集；应用的具体实现与工具操作配合 `$xbot-app-dev` 和当前项目约定。其他通用示例涉及入口、测试或默认值的写法与本页不一致时，以本页应用约定为准。

## 适用边界

| 项目 | 指令集开发 | 普通应用开发 |
| --- | --- | --- |
| 启动方式 | 由使用方调用具体公开指令 | 默认从主流程启动，再调用主运行模块的 `main(args)` |
| 启用禁用 | 维护指令眼睛、原型可见性和公开注册 | 不设置指令启用禁用；模块是否执行由实际调用链决定 |
| 描述面板 | 配置指令描述、动作描述、参数展示说明等 | 不制作指令中心专用描述面板；仍保留必要代码文档、运行参数及业务校验 |
| 测试入口 | 沿用指令集的测试函数约定 | 不设置测试入口，不需要测试函数，也不新增测试模块或测试流程 |
| 公开注册 | 维护原型及 Python/XML 公开成员，关注旧消费者兼容 | 内部模块通过流程调用或相对导入复用，不为它们新增公开指令注册 |
| 参数 | 面向使用方配置的指令 In/Out | 面向应用运行及内部模块传参；正式默认值仍在流程参数中配置 |
| 结果 | 重点是返回使用方声明的 Out | 重点是整次任务的结果、导出文件、处理明细和成功失败统计 |
| 验收交付 | 核验指令展示、安装和旧调用兼容 | 核验主流程完整运行、目标环境、依赖、资源路径和业务结果 |

应用没有指令面板，不代表没有输入输出。需要跨 Flow 传递的参数和 Out 仍按平台契约声明；普通 Python 函数正常使用参数和 `return`。应用调用已安装指令集，也不意味着应用内部模块需要变成公开指令。

不将 `opened`、`hidden` 或四层公开集合当成应用模块是否执行的判断依据，不机械套用指令注册维护步骤。保留客户端生成的文件及未知字段，不能因不需要公开指令就删除 `__init__.py` 或原型文件。应用仍可按职责组织分组，但不把分组当成指令启用清单。

## 模块组织

```text
平台主流程
  -> app_runner.main(args)
     -> 业务功能函数或业务模块
        -> utils 复用函数
```

`app_runner` 是英文模块名示例，不要求重命名现有主运行模块。保留平台主流程的启动身份，由主流程配置调用主运行模块；主运行模块必须从 `def main(args):` 开始执行，不能绕过它直接调用某个业务函数或依靠 import 副作用启动业务。

主流程保持简洁，主要负责参数传递和进入主运行模块。主运行模块组织配置读取、前置检查、业务编排、结果汇总、异常处理及资源释放；较大的业务功能按实际职责拆分，不把所有逻辑堆入主流程或 `utils`。

高复用操作正常拆入 `utils`，内部通过相对导入调用。`utils` 不负责启动整个应用，也不为单次业务步骤强建封装。`web_page.find_by_xpath(xpath).click()` 这类一行操作可以直接使用，无需额外包装；模块导入时不获取网页、执行写动作或启动业务。

沿用中文注释、英文模块和内部标识命名、参数定义及调用单行书写等代码约定；`print`、`sleep` 从 `xbot` 导入，尽量使用 `xbot` 对应功能而非 `xbot_visual`。维护既有应用时保留原流程参数名和外部契约，不顺带批量重命名。

业务功能函数同样遵循[业务步骤注释](code-execution.md#业务步骤注释)：在关键业务阶段前适当添加普通中文注释，不加序号、分割线或装饰性标题。

## 入口与参数

应用代码不新增 `test_*` 函数、独立测试入口或先测试再运行的分支。不得把指令集的 `if "xbot_extensions" in __file__` 跳过测试逻辑搬到应用中；应用不需要这种测试保护，也不应在正常启动时执行测试参数或测试后的 `exit()`。

主运行模块的 `main(args)` 直接使用 `args.get("参数名")`，不传第二个默认值参数，不使用 `or 默认值`、`setdefault` 等兜底。正式默认值在流程参数中设置；获取不到时按原值传递并进行业务校验，不在应用入口、业务函数或 `utils` 中补测试值。

`if args is None: args = {}` 只是容器处理，可以保留。涉及 Flow Out 时先声明再写回同一 `args`；普通函数返回值不能冒充平台 Out。已有项目配置或全局变量的来源保持明确，不擅自改成入口硬编码默认值。

## 运行与交付

主运行模块统一管理本次执行的状态和资源，只释放本次创建且由应用负责的资源，不随意关闭用户已有网页、窗口或连接。发生部分完成或结果未知时保留已确认明细，不自动重放整个任务；失败不能吞掉后伪装成功。

不需要测试入口或测试函数，不等于省略运行核验。获得相应授权后直接从正常主流程启动，检查配置传递、主运行模块入口、完整调用链、最终输出和异常处理。单独运行某个模块成功不能替代应用整体运行证据；未获授权的实际业务动作不执行，明确标记未验证。

交付时核对目标运行环境、依赖、登录权限、资源和输出路径；涉及定时或无人值守时再按实际需求验证其运行条件，不假定交互式运行成功就能无人值守。发布和同步仍需对应授权，不为验收自动发布应用。
