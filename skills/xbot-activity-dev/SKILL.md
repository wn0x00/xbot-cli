# 影刀指令开发规范

将业务能力实现为可配置、可调用、可维护的公开指令。内部 CodeFlow、测试模块与普通应用模块不自动成为公开指令；普通应用沿用正常主流程，不套用公开注册或测试分组要求。

<a id="tasks"></a>
## 先安排开发任务，再实施

开始开发时，先依据下表建立**本次可执行任务清单**，填写目标指令、当前状态和完成证据，再继续实施。有计划/待办工具时使用实际可用工具；没有时在对话中维护清单，不默认新建任务 Markdown。清单不是审批环节，除用户要求先评审外，安排后直接推进已授权工作，不只交计划就结束。

| 阶段 | 要安排的任务 | 完成依据 |
| --- | --- | --- |
| D1 范围与基线 | 读工程约定、app_id/namespace、引擎及当前源码；确认新增/扩展范围和旧消费者，改既有内容前留原文 | 目标清单、实际版本/来源、可恢复基线 |
| D2 规格与用例 | 确定业务对象、输入来源、In/Out、正式默认值、中文展示、成功/失败/未知语义和允许副作用 | 参数规格及按影响选定的验收用例；需评审时记录结果 |
| D3 业务实现 | 实现校验、对象确认、动作与结果核验，接入 main；需要测试时复用同一实现 | 实际代码、入口绑定和对既有契约的差异 |
| D4 平台配置 | 声明 In/Out 并核对默认值，配置标题/label/说明/动作描述；按需求安排公开状态和分组 | 参数回读；涉及的展示/注册/分组清单与实际结果 |
| D5 写入与静态 | 复核写前基线、按支持通道最小写入，回读并检查语法/静态诊断 | 实际 diff、写后源码/参数、检查结果；不是只做 dry-run |
| D6 运行与持久化 | 在任务范围内从正式入口验证真实输入消费、Out 和业务结果；影响旧调用时回归，涉及元数据时核验真实保存与完整重开 | run_id/终态、业务证据；适用的旧消费者、展示与重开证据 |
| D7 收尾与交付 | 恢复本任务临时值/辅助接线，检查未完成项，交付使用方式、结果与限制；发布仅在任务要求时另列 | 恢复回读、清单最终状态、实际保存/同步/发布层次 |

按指令和独立改动拆分子任务，避免多个入口共用一个笼统的“实现完成”。每项状态用“待处理、进行中、已完成、失败、受阻、不适用”，同时留一条结果/证据。阶段完成、失败或范围变化时及时更新；续接任务先核对清单和现场，不重复已生效动作。

阶段是覆盖检查，不要求机械建立七条待办。单个小指令可合并呈现，多个指令、消费者或可独立失败的修改须拆开。每项写清“目标 → 具体动作 → 阶段 → 状态 → 证据/缺口”。例如新建 `normalize_text` 时，初始清单可如下安排；表内是待执行示例，不是已完成记录：

| 具体任务 | 覆盖阶段 | 初始状态与预期证据 |
| --- | --- | --- |
| 确认 normalize_text 所属工程、text/result 契约和平台空串默认值 | D1–D2 | 待处理；工程身份、规格及基线 |
| 适配完整示例，写入 normalize_text 并声明 In/Out，回读检查 | D3–D5 | 待处理；实际 diff、参数和静态结果 |
| 从正式入口验证普通/空/非法输入，核对 Out；涉公开状态再验注册重开 | D6 | 待处理；实际运行与输出，适用的持久化证据 |
| 恢复临时输入/辅助，核对清单并交付使用方法 | D7 | 待处理；恢复回读、未完成项及交付层次 |

仅为修复既有故障而调整参数，仍由 fix 组织任务并引用本文件契约；用户要求新增行为或新参数能力时由 dev 组织，避免同一项维护重复建两套清单。

“不适用”仅用于本次范围确实不涉及的步骤，并写原因；缺账号、环境或权限导致必需验收无法执行，应标“受阻”，不能改成已完成。命令返回 ok、模拟通过或静态通过不能替代 D6 的真实证据。交付前逐项核对：必需项全部完成才能报告开发完成，否则明确本地候选及剩余工作，不强行执行未获授权的业务或发布。

保持一个指令对应可理解的业务动作，相近操作可用少量枚举合并。需要文案、公开状态或分组配置时，只读 [元数据参考](references/metadata.md) 的对应章节；源码小修不强加全套元数据流程。不凭开发机解释器推断影刀引擎，未确认时沿用 Python 3.7 兼容语法。

已有指令报错先走 [维护流程](../xbot-activity-fix/SKILL.md)，确认补丁涉及哪个契约后再读本文件；命令用法查 [xbot-cli-doc](../xbot-cli-doc/SKILL.md)。

## 参数与中文面板

| 内容 | 要求 |
| --- | --- |
| 新文件、函数、变量、In/Out | 英文 snake_case；保留既有命名空间、外部参数和绑定，不为风格改名 |
| 标题、label、说明、业务展示 | 清楚的中文；标题表达对象与动作，描述说明范围、条件和副作用 |
| 参数契约 | 名称、方向、真实类型、必填/条件、默认值、空值语义、上游来源与下游用途 |
| 参数说明 | 格式/单位、业务含义、适当示例、默认/空值；按需注明互斥、时区/边界、数量覆盖和文件真实类型 |
| 编辑器 | 固定枚举用下拉，二元值用复选，数量用数值，多对象用列表/对象变量，文件用已验证文件编辑器；不让用户抄内部 ID 或缓存路径 |
| 输出 | 类型稳定、可继续操作；保留原始记录及真实时间，必要时另给简明展示，不用当前时间填缺失值 |

编辑器能力以同版本有效样本或 schema 为准。枚举展示中文、内部 value 稳定。区分缺失、空串、空列表、零、False、None 和未知；条件必填、互斥及不适用行为在说明与运行校验中一致，不静默忽略冲突输入。

正式默认值配置在流程 In，并与原型一致；新增可选参数用兼容默认值。删除参数、变更类型/输出、公开身份或异常语义，须明确消费者迁移，不能当作纯文案美化。弃用、仅隐藏、注销分别处理，见 [公开状态](references/metadata.md#enable)。

## CodeFlow、业务实现与测试

入口读取 In、调用业务函数、将已声明 Out 写回**原 args**。完整最小示例放在 [入口模板](assets/activity-entry.py)，内含 `normalize_text` 与 main，无外部业务模块依赖；[测试模板](assets/activity-test.py) 调用该同一实现，断言输入消费、Out、调用方字段保留、空值及非法输入，不只打印或返回结果。

在本 skill 目录可直接离线运行，不连接影刀或执行业务写动作：

```powershell
python -B -X utf8 assets/activity-test.py -v
```

接入客户端时，用受支持流程接口将入口内容写为 `normalize_text` CodeFlow；依据 [In/Out JSON](assets/flow-params.example.json) 声明 In `text:str`（正式默认值空串）和 Out `result:str`。测试源码如需接入，使用 `test_normalize_text` 模块；模板按包相对加载正式模块并保留可能同名的公开包装绑定，仅显式执行测试，不自动公开或接入正常主流程。离线模板通过之后，D4–D6 的客户端写入、回读和原入口验收仍单独完成。

实际业务可按职责拆到相对导入模块；无需为这个小例子强拆文件。仅 args 为 None 时创建容器，不用 `args or {}` 替换空容器；Python return 不代替 Flow Out。main 直接 `args.get("name")`，不提供第二默认值、不用 or/setdefault 或缺值分支填样例。必填不合法由业务校验报错，保留平台传来的空值含义；本例直接传入缺失/None 时会报错，不会自行补平台默认值。

业务函数执行“校验 → 确认对象 → 动作 → 核验结果”，说明输入、输出、副作用和限制；相对导入依照当前模板，不在 import 执行业务。仅在确有职责或复用时拆模块，避免空转发层。复杂或关键阶段前用必要的中文目的注释，简单代码不机械逐行标注，也不加序号和装饰分隔。

测试具体值只放在 `test_*` 内，调用同一正式业务实现，不复制动作逻辑、不把样例放模块常量或业务默认形参；默认不公开、不随主流程或 import 自动执行。真实写操作按已授权对象与范围测试。普通应用只为复现创建的临时辅助，结束后恢复，不保留正式测试入口。

模板实现的是去除文本首尾空白这一小功能；改为其他业务时同步调整函数、In/Out 和断言，不保留示例默认值或未实现的 service 引用。

## 执行与自动化约定

- 批次先校验全部基础输入与对象，逐项记录进度；区分未执行、确认成功、确认失败、结果未知。保留异常链和部分结果，不吞错返回成功或空列表。
- 只读暂时错误可有限重试；提交、发送等结果未知先对账，不换定位/通道或整批重放。补偿需要明确业务语义，不能自动删用户数据。
- 宣称全量读取须证明分页终止、稳定排序、跨页身份与覆盖，处理重复键和分片失败，不用大 limit 代替完整性。优先公开 API；必要的内部读取隔离为版本适配，不修改上游数据库。
- Web 先核对页面对象来源、账号、记录和区域，查询当前 SDK 签名。普通 DOM 使用已验证的 XPath；单目标唯一，集合按业务键，不取首项。父元素内用相对定位；iframe/Shadow 按真实 Selector 协议，不能把分段路径当普通 XPath。
- 旧新候选在动作前查找、按实际节点去重和消歧，不能捕获点击异常后换另一个点。先等待业务就绪并核对遮挡，页面跳转后重取对象；动作后查回执，点击返回不证明业务成功。
- Windows 核对业务程序、进程实例、窗口和控件；限制树遍历区域/深度/节点/时间。实时控件推导点击点，不固化旧坐标、PID/HWND 或 UIA RuntimeId；不关闭无关窗口来解除遮挡。
- 应用依赖通过 `python package` 管理并保存约束，不用系统 pip。文件须核验真实格式和必要解码，不换扩展名冒充格式、不覆盖已有文件；临时资源明确生命周期。

命令细节按 [CLI 参考](../xbot-cli-doc/references/operations.md)，已有网页或原生定位故障分别读 fix 的 [Web](../xbot-activity-fix/references/web-repair.md)／[Windows](../xbot-activity-fix/references/windows-repair.md)，无需预先加载两份。

## 规格与验收模板

需要规格时直接使用以下字段，不另建固定 Markdown 模板文件：

| 规格项 | 填写内容 |
| --- | --- |
| 身份与范围 | app_id、namespace、中文指令名、稳定文件/函数、新增或改造、旧消费者 |
| 业务 | 对象与动作、输入来源、前置、允许副作用、独立成功证据、失败与未知的处理 |
| 每项 In/Out | 内部名、中文 label、类型/编辑器、必填与条件、正式默认/空值、上下游用途 |
| 实现与兼容 | 业务函数、入口绑定、依赖版本、保留/迁移的参数、输出和异常语义 |
| 用例 | 输入摘要、允许动作、预期、实际、运行 ID、业务证据及未验证项 |

按改动风险选用例：正常/默认输入、缺失/空值/类型错误、无数据、重名/过期/跨账户对象、分页、批次中断/未知、文件格式及不覆盖。新增定位兼容逻辑时补旧版、新版、共存、歧义拒绝；无法取得的环境明确未验证，不为造场景改生产页面。

交付先对照 D1–D7 收齐状态，再在对话或用户要求的报告中用一张证据表呈现结果；清单跟踪过程，证据表支持结论，不把未完成项隐藏在报告里：

| 检查面 | 结果与证据 |
| --- | --- |
| 写入/静态 | 实际 diff、回读、语法/检查结果；dry-run 仅是输入预览 |
| 原入口运行/业务 | 实际入口和输入消费、run_id/task_id、Out、独立业务回执、部分结果 |
| 元数据（涉及时） | 展示与四层绑定、真实保存、关闭 false/打开 true、完整重开及稳定比较 |
| 兼容/交付 | 原配置旧消费者、临时恢复、发布/安装/使用方版本及具体限制 |

分别标记通过、失败、未执行、受阻或未知。`flow check` 是静态，verify 会运行，超时续查原 ID；本地保存、同步、发布、使用方恢复各自给证据。元数据检查器不能代替真实展示或业务验收。sync 可直接用于正常关闭，不影响指令，也不为它另外询问确认。
